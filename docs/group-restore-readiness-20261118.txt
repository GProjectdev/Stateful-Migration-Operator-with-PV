Full-group restore readiness barrier fix — 2026-11-18

Observed failure
The four-rank GPT-2 component acceptance used four distinct g6.xlarge GPU
workers in aws1, one rank/GPU per VM, full durable checkpoint and one new OD
worker. All four checkpoint archives were exported and all source Pod UIDs
were positively fenced. The prepare Job succeeded, and restored trainer
containers were Running, but their TCP control-port readiness probes stayed
false. Only the restored launcher process remained: it was waiting on the
operation-owned lock and its REST server was intentionally closed.

Cause
internal/member/reconciler.go required PodReady before resumeGroup could
create the resume Job. fluidcr/launcher.py closes its REST server before the
CRIU checkpoint and starts it only after lock removal. group_restore.py
prepare_group creates those locks, and resume_group releases them. A control
port readiness probe therefore produced a circular dependency. This is not a
DDP rank-count limitation or a reason to weaken UID/source-fencing guards.

Change
internal/member/group.go: groupContainersRunning requires each mapped archive
container to have Running state and a nonempty CRI container ID.
internal/member/reconciler.go allows the existing operation-owned resume Job
only after all mapped Pods/containers are Running on their exact target nodes.
All existing plan UID/generation, source fencing, current artifact, target node
capability, injection and shared-PVC validation still precede this release.
The phase remains Resuming until all target Pods become Ready. Management
Verified still requires fresh post-resume TrainingRuntime progress; no status
is manually promoted and no finalizer is bypassed.

Regression evidence
internal/member/group_test.go TestGroupEndToEndFencingPrepareAdmissionResume
now models the actual closed-control-port state. It verifies that Waiting
containers cannot create the resume Job; Running but unready mapped containers
can release the existing barrier; a completed resume Job alone cannot certify
Running; Ready is still required afterward. Existing management/fencing tests
and the complete go test ./... suite passed. No CRD or upstream Karmada change.
